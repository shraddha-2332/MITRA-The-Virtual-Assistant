## PROJECT TITLE

**MITRA: The Virtual Assistant**

The title is retained as requested for the college-sponsored project. The report body should continue to describe the implemented system accurately and should not expand MITRA into unsupported capabilities.

## ABSTRACT

Higher education institutions publish admission information through web pages, notices, fee circulars, programme tables and frequently asked question documents. Students and parents need reliable answers about admission routes, programmes, eligibility, fees, scholarships, hostel facilities and official contacts. Static documents are difficult to search when queries contain paraphrases, spelling variations, compound requests or regional languages. Unrestricted generative artificial intelligence can also produce unsupported information.

This project presents **MITRA: The Virtual Assistant**, developed for MIT College of Railway Engineering and Research (MITCORER), Barshi. MITRA is a web-based institutional assistant that provides admission and campus information through maintained knowledge, source-aware retrieval and deterministic factual answers. The frontend uses React and Vite, the backend uses Node.js, and SQLite stores knowledge records, source metadata, revisions and application data.

Before answering a request, MITRA validates input and applies bounded query understanding. It identifies selected details such as programme branch, admission route, academic year, category, gender and facility scope. It supports selected English, Marathi, Hindi and transliterated queries, including common paraphrases, plurals, limited spelling corrections, compound questions and clarification requirements. Critical facts such as fee structures, programme intake, choice codes and hostel or mess charges are answered from maintained published records instead of being freely generated by a language model.

The system uses weighted lexical retrieval, conceptual scoring and optional Gemini vector similarity when configured. Gemini is used only as an evidence-grounded component for selected open-ended questions. Generated responses are checked against retrieved evidence for important factual values, while unsupported promises concerning admission, placement, scholarships or seat allocation are rejected. Knowledge maintenance uses role-based access control, revision checks, publication states and source-provenance metadata. A website synchronization module stages detected changes for maintainer review without automatic publication. The prototype has been validated through automated tests and browser-based answer audits. Independent human evaluation, broader language review and deployment verification remain future work.

**Keywords:** institutional virtual assistant, admission information system, retrieval-augmented generation, multilingual query understanding, source provenance, deterministic factual answering, Gemini API.

## Claims deliberately excluded from this replacement

Do not include the following claims unless future independent evidence is obtained:

- 100% factual accuracy or zero hallucination.
- A validated 360-case multi-turn benchmark.
- Sub-second mean latency or any latency value that has not been measured and reported.
- Production or enterprise deployment.
- A constrained-decoding model, Gemini response-schema ingestion, or JSON-schema-enforced extraction pipeline.
- Public multi-turn context condensation or coreference resolution.
- Native-level Marathi/Hindi fluency.
- A high-precision or superior hybrid retrieval result without an independently reviewed comparison.
- Fully automated handoff to dedicated admissions staff, unless a real operational workflow and staff ownership are established.
